## 1. Название и организация

- Название системы: КонтрОрдер (АИС «Учёт заказов контроллеров»)
- Организация / подразделение: АО «НИЦ «Инкомсистем»», производственный участок
- № из таблицы примеров (если брали): собственная тема — «Разработка системы учёта заказов контроллеров на предприятии»

## 2. Главная сущность и справочник

- Главный объект (одна запись процесса): Заказ на контроллер — запись о заказе на изготовление и отгрузку контроллеров с указанием модели, количества и требований заказчика
- Справочник (вторая таблица, ссылка числом): Модель контроллера — каталог моделей, которые выпускает предприятие (например, ПЛК-110, ПЛК-120, МВ-8DI8DO, МВ-8AI, КСУ-300)
- Поле-ссылка (как назовём в JSON/БД): `modelId` (число, FK на таблицу `ControllerModels`)

## 3. Роли и права

| Роль                                         | Создаёт | Назначает | Меняет статус                                  |
| -------------------------------------------- | ------- | --------- | ---------------------------------------------- |
| Менеджер по заказам (Manager)                | да      | нет       | нет                                            |
| Начальник производственного участка (Chief)  | нет     | да        | да (отмена любого незавершённого заказа)       |
| Инженер-наладчик (Engineer)                  | нет     | нет       | да (в производство, отгрузка и отмена своих)   |

Исполнитель (инженер-наладчик) не назначает себя: назначение делает только начальник участка.

## 4. Сценарий в одно предложение

Менеджер по заказам создаёт заказ на контроллер → начальник участка назначает инженера-наладчика → инженер переводит заказ в производство и после отгрузки закрывает его (или отменяет).

## 5. Терминология

| Понятие                  | В проекте                                                       |
| ------------------------ | --------------------------------------------------------------- |
| Главный объект           | заказ на контроллер (`Order`), путь API `/api/orders`           |
| Справочник               | модель контроллера (`ControllerModel`), поле-ссылка `modelId`   |
| Кто создаёт              | менеджер по заказам                                             |
| Кого назначают           | инженер-наладчик                                                |
| Кто смотрит сводку       | начальник производственного участка                             |
| Статус «принят»          | `New`                                                           |
| Статус «в производстве»  | `InProgress`                                                    |
| Статус «отгружен»        | `Closed`                                                        |
| Статус «отменён»         | `Cancelled`                                                     |
| Наименование заказа      | `title`                                                         |
| Описание заказа          | `description` — комплектация, количество, требования заказчика  |
| Машинный идентификатор   | `id` (целое число)                                              |
| Человеческий номер       | `number`, например `ЗК-2026-0001`                               |

## 6. Что не входит в семестр

1. Интеграция с ERP/1С и бухгалтерским учётом предприятия.
2. Автоматическое формирование спецификаций и конструкторской документации.
3. Мобильное приложение для сборочного участка.
4. Считывание штрих-кодов/QR готовых изделий и интеграция с оборудованием стенда проверки.
5. Уведомления (email, push, SMS) о смене статуса заказа.

## 7. Запас под ВКР

1. **Данные/процесс:** учёт серийных номеров и результатов приёмо-сдаточных испытаний каждого контроллера с формированием паспорта изделия.
2. **Связь с другими системами:** интеграция с ERP/1С для автоматической загрузки заказов покупателей и выгрузки данных об отгрузке.
3. **Масштаб:** расширение на все производственные участки предприятия и подсистема сводной аналитики (сроки изготовления, загрузка инженеров).
4. **Данные/процесс:** прогнозирование потребности в комплектующих на основе истории заказов и контроль остатков на складе.
