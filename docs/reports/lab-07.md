## 1. Цель работы

В папке `/backend` поднять каркас серверного приложения на ASP.NET Core Web API на порту `5000` со страницей документации Swagger (`/swagger`) в среде `Development`, служебными маршрутами `GET /health` и `GET /info`, подготовленными слоями (`Controllers`, `Services`, `Models`, `Data`) и регистрацией сервиса через Dependency Injection (DI); описать воспроизводимый запуск и ограничения этапа в корневом `README.md`.

## 2. Структура и внедрение зависимостей

В `backend/` подготовлены слои:
- `Controllers/SystemController.cs` — служебные маршруты `GET /health` и `GET /info`;
- `Services/IOrderService.cs` и `Services/OrderService.cs` — интерфейс и сервис предметной области КонтрОрдер;
- `Models/` — модель заказа;
- `Data/.gitkeep` — заготовка слоя доступа к данным.

В `Program.cs` сервис регистрируется через DI:

```csharp
builder.Services.AddSingleton<IOrderService, OrderService>();
```

**Сервис зарегистрирован через DI, чтобы контроллер не создавал реализацию через new.**

## 6. Ответы на вопросы для устной защиты

### 1. Чем C# отличается от ASP.NET Core?
C# — язык программирования (классы, методы, типы в файлах `.cs`). ASP.NET Core — серверный веб-фреймворк на платформе .NET: он слушает порт, принимает HTTP-запросы, направляет их в контроллеры, превращает ответы в JSON и поднимает Swagger.

### 2. Зачем нужен DI, если можно написать `new`?
Если написать `new OrderService()` внутри контроллера, он навсегда привязан к конкретному классу. Когда хранение в памяти заменят на PostgreSQL, пришлось бы переписывать контроллеры. При DI контроллер просит в конструкторе интерфейс `IOrderService`, а реализация подставляется в одном месте — в `Program.cs`.

### 3. Что доказывает `200 OK` от `GET /health`?
Только то, что процесс ASP.NET Core запущен, слушает порт `5000` и отвечает на запросы. Он не доказывает, что работают создание заказов, проверка полей или сохранение данных.

### 4. Почему создание заказа ещё не готово в ЛР7?
Задача ЛР7 — воспроизводимый серверный каркас: порт, Swagger, слои и DI. Чтение и создание главного объекта с проверкой правил (`GET` и `POST`) выделены в ЛР8.
