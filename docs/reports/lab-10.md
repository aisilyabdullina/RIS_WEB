## 3. Пакеты, секреты и миграции

1. **Пакеты в `backend/backend.csproj`:**
   - `Microsoft.EntityFrameworkCore.Design` версии `8.0.11`
   - `Npgsql.EntityFrameworkCore.PostgreSQL` версии `8.0.11`
2. **Строка подключения хранится вне Git** через `dotnet user-secrets`:
   ```bash
   cd backend
   dotnet user-secrets init
   dotnet user-secrets set "ConnectionStrings:Default" "Host=localhost;Port=5432;Database=kontrorder;Username=postgres;Password=ВАШ_ПАРОЛЬ"
   ```
   В `backend/appsettings.json` значение `ConnectionStrings:Default` пустое, а в Git лежит шаблон `backend/appsettings.example.json` без реального пароля.
3. **Миграция:**
   ```bash
   cd backend
   dotnet ef migrations add InitialCreate
   dotnet ef database update
   ```
   Файлы `InitialCreate.cs`, `InitialCreate.Designer.cs` и `AppDbContextModelSnapshot.cs` из папки `backend/Migrations/` добавлены в Git.
4. **Начальные данные.** При запуске `Program.cs` применяет миграции методом `Migrate()`, а `DbSeeder.SeedIfEmpty` заполняет пустые таблицы теми же данными, что и `db/seed.sql`.

## 4. Что изменилось в сервисе

`OrderService` получает `AppDbContext` через конструктор и регистрируется как `Scoped`, потому что контекст базы живёт один HTTP-запрос. Все пять операций работают с таблицами:

- `GET /api/orders` и `GET /api/orders/{id}` читают из `orders` без отслеживания изменений (`AsNoTracking`);
- `POST /api/orders` проверяет поля, наличие модели в справочнике и пользователя-создателя, сохраняет заказ, затем присваивает номер `ЗК-2026-NNNN` по идентификатору, который выдала база;
- `PATCH .../assignee` проверяет, что пользователь существует и является инженером (`Engineer`), и сохраняет `assignee_user_id`;
- `PATCH .../status` проверяет допустимость перехода и наличие исполнителя для `InProgress`, затем сохраняет `status`.

## 5. Рестарт-тест

### Шаг 1. Создание заказа до остановки сервера

```bash
curl -i -X POST http://localhost:5000/api/orders \
  -H "Content-Type: application/json" \
  -d '{"title":"Контроллеры для линии упаковки","modelId":2,"description":"6 шт., интерфейс Modbus TCP, исполнение для работы при температуре до +70 °C"}'
```

Ответ `201 Created`:

```json
{
  "id": 6,
  "number": "ЗК-2026-0006",
  "title": "Контроллеры для линии упаковки",
  "modelId": 2,
  "description": "6 шт., интерфейс Modbus TCP, исполнение для работы при температуре до +70 °C",
  "status": "New",
  "createdAt": "2026-11-20T14:12:07.318452Z",
  "createdByUserId": 1,
  "assigneeUserId": null
}
```

Зафиксировано: `id = 6`, `number = "ЗК-2026-0006"`, `status = "New"`.

### Шаг 2. Перезапуск сервера

Сервер остановлен клавишами `Ctrl+C` и запущен заново командой `dotnet run`.

### Шаг 3. Чтение после перезапуска

```bash
curl -i http://localhost:5000/api/orders/6
```

Ответ `200 OK` содержит тот же заказ: `id`, `number`, `title`, `modelId` и `status` совпадают с ответом до перезапуска.

### Шаг 4. Проверка в базе

```sql
SELECT id, number, title, status
FROM orders
WHERE id = 6;
```

```text
 id |    number    |             title              | status
----+--------------+--------------------------------+--------
  6 | ЗК-2026-0006 | Контроллеры для линии упаковки | New
(1 row)
```

### Шаг 5. Оба `PATCH` сохраняются в базе

- `PATCH /api/orders/6/status` с телом `{"status": "InProgress"}` до назначения исполнителя возвращает `409 Conflict`.
- `PATCH /api/orders/6/assignee` с телом `{"assigneeUserId": 5}` возвращает `200 OK`, в таблице `orders` у строки 6 заполняется `assignee_user_id = 5`.
- Повторный `PATCH /api/orders/6/status` с телом `{"status": "InProgress"}` возвращает `200 OK`, в таблице `orders` у строки 6 значение `status = 'InProgress'`.
