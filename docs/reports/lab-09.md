## 2. Схема базы данных (`db/schema.sql`)

Схема соответствует ER-модели из `docs/data-model.md` и находится в третьей нормальной форме.

1. **`controller_models`** — справочник моделей контроллеров:
   - `id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
   - `name text NOT NULL UNIQUE` — наименование (ПЛК-110, ПЛК-120, МВ-8DI8DO, МВ-8AI, КСУ-300)
   - `article text NOT NULL UNIQUE` — артикул
   - `controller_type text NOT NULL` — тип контроллера
   - `io_count integer NOT NULL` — количество каналов ввода-вывода
   - `protocol text NOT NULL` — протокол связи
   - `stock_qty integer NOT NULL DEFAULT 0` — остаток на складе
2. **`users`** — сотрудники:
   - `id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
   - `full_name text NOT NULL`
   - `email text NOT NULL UNIQUE`
   - `role text NOT NULL`, ограничение `users_role_check CHECK (role IN ('Manager', 'Chief', 'Engineer'))`
3. **`orders`** — главный объект, заказы на контроллеры:
   - `id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
   - `number text NOT NULL UNIQUE` — регистрационный номер (`ЗК-2026-0001`)
   - `title text NOT NULL`, ограничение `orders_title_len_check` (5–80 символов после `btrim`)
   - `description text NOT NULL`, ограничение `orders_description_len_check` (10–500 символов после `btrim`)
   - `model_id integer NOT NULL REFERENCES controller_models (id)` — внешний ключ на справочник
   - `status text NOT NULL DEFAULT 'New'`, ограничение `orders_status_check` на четыре значения (`New`, `InProgress`, `Closed`, `Cancelled`)
   - `created_at timestamptz NOT NULL DEFAULT now()`
   - `created_by_user_id integer NOT NULL REFERENCES users (id)` — создатель заказа
   - `assignee_user_id integer NULL REFERENCES users (id) ON DELETE SET NULL` — исполнитель; у нового заказа не заполнен

### Индексы

- `CREATE INDEX orders_status_idx ON orders (status);` ускоряет выборку заказов по статусу (`WHERE status = 'New'`) и подсчёт по статусам (`GROUP BY status`).
- `CREATE INDEX orders_model_id_idx ON orders (model_id);` ускоряет соединение `orders` со справочником моделей и фильтрацию по модели.

### Повторный запуск схемы

В начале `db/schema.sql` стоят команды `DROP TABLE IF EXISTS ... CASCADE` в порядке, обратном зависимостям (`orders`, `users`, `controller_models`). Поэтому скрипт можно запускать повторно на учебной базе без ошибок о существующих объектах.

### Порядок запуска

```bash
psql -U postgres -c "CREATE DATABASE kontrorder;"
psql -U postgres -d kontrorder -f db/schema.sql
psql -U postgres -d kontrorder -f db/seed.sql
psql -U postgres -d kontrorder -f db/queries.sql
```

## 4. Результаты запросов (`db/queries.sql`)

### 4.1. Фильтр и сортировка

```sql
SELECT number, title, status, created_at
FROM orders
WHERE status = 'New'
ORDER BY created_at DESC;
```

```text
    number    |                     title                     | status |       created_at
--------------+-----------------------------------------------+--------+------------------------
 ЗК-2026-0005 | Модули ввода-вывода для компрессорной станции | New    | 2026-11-05 11:00:00+03
 ЗК-2026-0001 | Контроллеры для линии фасовки                 | New    | 2026-11-01 09:15:00+03
(2 rows)
```

### 4.2. `JOIN` со справочником и пользователями

```sql
SELECT
    o.number,
    o.title,
    m.name AS model_name,
    u_creator.full_name AS created_by,
    COALESCE(u_assignee.full_name, 'Не назначен') AS assignee_name,
    o.status,
    o.created_at
FROM orders AS o
JOIN controller_models AS m ON m.id = o.model_id
JOIN users AS u_creator ON u_creator.id = o.created_by_user_id
LEFT JOIN users AS u_assignee ON u_assignee.id = o.assignee_user_id
ORDER BY o.created_at DESC;
```

В результате выводится название модели `model_name`, а не только числовой `model_id`:

```text
    number    |                     title                     | model_name |         created_by         |       assignee_name       |   status   |       created_at
--------------+-----------------------------------------------+------------+----------------------------+---------------------------+------------+------------------------
 ЗК-2026-0005 | Модули ввода-вывода для компрессорной станции | МВ-8DI8DO  | Мустафина Ляйсан Рашитовна | Не назначен               | New        | 2026-11-05 11:00:00+03
 ЗК-2026-0004 | Партия ПЛК-120 для котельной                  | ПЛК-120    | Мустафина Ляйсан Рашитовна | Не назначен               | Cancelled  | 2026-11-04 16:45:00+03
 ЗК-2026-0003 | Контроллер локальной автоматики КСУ           | КСУ-300    | Мустафина Ляйсан Рашитовна | Сафина Гульнара Маратовна | Closed     | 2026-11-03 14:20:00+03
 ЗК-2026-0002 | Модули аналогового ввода для насосной станции | МВ-8AI     | Мустафина Ляйсан Рашитовна | Ахметов Рустем Данилович  | InProgress | 2026-11-02 10:30:00+03
 ЗК-2026-0001 | Контроллеры для линии фасовки                 | ПЛК-110    | Мустафина Ляйсан Рашитовна | Не назначен               | New        | 2026-11-01 09:15:00+03
(5 rows)
```

Для заказов без исполнителя используется `LEFT JOIN`: при обычном `JOIN` такие строки пропали бы из результата.

### 4.3. `GROUP BY` по статусам

```sql
SELECT status, COUNT(*) AS count
FROM orders
GROUP BY status
ORDER BY status;
```

```text
   status   | count
------------+-------
 Cancelled  |     1
 Closed     |     1
 InProgress |     1
 New        |     2
(4 rows)
```

### 4.4. Проверка ограничения `CHECK`

```sql
INSERT INTO orders (number, title, description, model_id, status, created_by_user_id)
VALUES ('ЗК-2026-9999', 'Проверка недопустимого статуса Done',
        'Эта строка должна быть отклонена ограничением CHECK в PostgreSQL', 1, 'Done', 1);
```

```text
ERROR:  new row for relation "orders" violates check constraint "orders_status_check"
DETAIL:  Failing row contains (6, ЗК-2026-9999, Проверка недопустимого статуса Done, Эта строка должна быть отклонена ..., 1, Done, ..., 1, null).
```

Эта вставка не входит в `db/seed.sql` и оставлена в `db/queries.sql` закомментированной.
