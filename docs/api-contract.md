## 1. Таблица маршрутов API

| Метод и путь                       | Тело (что прислать)                 | Успех                                                    | Возможная ошибка                                                         |
| ---------------------------------- | ----------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------ |
| `POST /api/auth/login`             | `login`, `password`                 | `200 OK`, `token`, `userId`, `role`, `fullName`          | `401 Unauthorized` (неверный логин или пароль)                           |
| `GET /api/orders`                  | — *(опционально query: `status`, `assigneeUserId`)* | `200 OK`, массив заказов или `[]`        | —                                                                        |
| `GET /api/orders/{id}`             | —                                   | `200 OK`, один заказ                                     | `404 Not Found`                                                          |
| `POST /api/orders`                 | `title`, `modelId`, `description`   | `201 Created`, в ответе `id`, `number`, `status: "New"`  | `400 Bad Request` (ошибка проверки полей), `403 Forbidden` (не менеджер) |
| `PATCH /api/orders/{id}/assignee`  | `assigneeUserId`                    | `200 OK`, обновлённый заказ                              | `400`, `403 Forbidden` (не начальник участка), `404`, `409` (заказ завершён) |
| `PATCH /api/orders/{id}/status`    | `status`                            | `200 OK`, обновлённый заказ                              | `400`, `403 Forbidden` (чужой заказ), `404`, `409 Conflict` (недопустимый переход или нет исполнителя) |
| `GET /api/models`                  | —                                   | `200 OK`, справочник моделей контроллеров                | —                                                                        |
| `GET /api/users?role=Engineer`     | —                                   | `200 OK`, список инженеров `{id, fullName}`              | —                                                                        |

## 2. Важные ограничения контракта

1. **Поля, формируемые сервером.** При создании (`POST /api/orders`) клиент не присылает `id`, `number`, `status` и `assigneeUserId`. Сервер сам ставит `status = "New"`, `assigneeUserId = null`, `number = "ЗК-2026-0001"`.
2. **Два разных `PATCH`.** Назначение исполнителя (`/assignee`) и смена статуса (`/status`) — отдельные маршруты, чтобы разделить права ролей и не затереть чужое поле.
3. **Нет `DELETE`.** Отмена заказа — это смена статуса на `Cancelled`.
4. **Чистые REST-пути.** Пути вида `/api/orders/create` не используются: действие определяется HTTP-методом.
5. **Пустой список — не ошибка.** Если заказов нет, `GET /api/orders` возвращает `200 OK` и `[]`, а не `404`.
6. **Статусы.** Допустимы только `New`, `InProgress`, `Closed`, `Cancelled` (написание строго такое).

## 3. Примеры запросов и ответов

### 3.1. Создание заказа (критерий 1)

Запрос: `POST /api/orders`

```json
{
  "title": "Контроллеры для линии фасовки",
  "modelId": 1,
  "description": "10 шт., интерфейс Modbus RTU, исполнение для цеха с повышенной температурой"
}
```

Ответ (`201 Created`):

```json
{
  "id": 17,
  "number": "ЗК-2026-0017",
  "title": "Контроллеры для линии фасовки",
  "modelId": 1,
  "description": "10 шт., интерфейс Modbus RTU, исполнение для цеха с повышенной температурой",
  "status": "New",
  "createdByUserId": 1,
  "assigneeUserId": null,
  "createdAt": "2026-11-06T09:30:00Z",
  "updatedAt": "2026-11-06T09:30:00Z"
}
```

Ответ при ошибке проверки полей (`400 Bad Request`):

```json
{
  "title": "Ошибка проверки полей",
  "status": 400,
  "errors": {
    "title": ["Поле title должно содержать от 5 до 80 символов."],
    "modelId": ["Поле modelId (siteId) должно быть целым числом больше нуля."]
  }
}
```

### 3.2. Назначение исполнителя (критерий 2)

Запрос: `PATCH /api/orders/17/assignee`

```json
{
  "assigneeUserId": 5
}
```

Ответ (`200 OK`):

```json
{
  "id": 17,
  "number": "ЗК-2026-0017",
  "title": "Контроллеры для линии фасовки",
  "status": "New",
  "assigneeUserId": 5
}
```

### 3.3. Перевод заказа в производство (критерий 3)

Запрос: `PATCH /api/orders/17/status`

```json
{
  "status": "InProgress"
}
```

Ответ (`200 OK`):

```json
{
  "id": 17,
  "number": "ЗК-2026-0017",
  "status": "InProgress",
  "assigneeUserId": 5
}
```

Ответ при переводе в `InProgress` без исполнителя (`409 Conflict`):

```json
{
  "title": "Конфликт состояния процесса",
  "status": 409,
  "detail": "Нельзя перевести заказ в статус InProgress, пока не назначен исполнитель (assigneeUserId)."
}
```

Ответ при недопустимом переходе (`409 Conflict`):

```json
{
  "title": "Конфликт состояния процесса",
  "status": 409,
  "detail": "Нельзя перевести заказ из статуса Closed в статус InProgress."
}
```

Ответ при попытке изменить чужой заказ (`403 Forbidden`, после подключения авторизации):

```json
{
  "error": "Forbidden",
  "message": "Инженер может менять статус только своих заказов"
}
```
