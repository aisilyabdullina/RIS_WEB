## 1. Обязательная матрица для трёх критериев приёмки ЛР1

| Требование ЛР1                    | Поле или сущность                                                   | Запрос                              | Критерий   |
| --------------------------------- | ------------------------------------------------------------------- | ----------------------------------- | ---------- |
| Менеджер создаёт заказ            | `Order`, `title`, `modelId`, `description` (ответ: `id`, `number`, `status: New`) | `POST /api/orders`        | Критерий 1 |
| Начальник участка назначает инженера | `Order.assigneeUserId` (FK → `User.id`)                          | `PATCH /api/orders/{id}/assignee`   | Критерий 2 |
| Инженер переводит заказ в производство | `Order.status` (`New` → `InProgress`)                          | `PATCH /api/orders/{id}/status`     | Критерий 3 |

---

## 2. Полная трассировка функциональных требований ФТ-1 … ФТ-8

| Код ФТ   | Содержание требования (из `lab-01-requirements.md`)                          | Сущности и поля                                              | Метод и путь                                 | Код ответа            |
| -------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------- | --------------------- |
| **ФТ-1** | Менеджер создаёт заказ; получает `New` и номер `ЗК-2026-0001`                 | `Order` (`id`, `number`, `title`, `modelId`, `description`, `status`) | `POST /api/orders`                  | `201 Created` / `400` |
| **ФТ-2** | Начальник участка назначает исполнителя отдельным действием                   | `Order.assigneeUserId`, `User.id`                            | `PATCH /api/orders/{id}/assignee`            | `200 OK` / `404` / `409` |
| **ФТ-3** | Инженер переводит свой заказ `New` → `InProgress` (нужен исполнитель)         | `Order.status`, `Order.assigneeUserId`                       | `PATCH /api/orders/{id}/status`              | `200 OK` / `409`      |
| **ФТ-4** | Инженер переводит свой заказ в `Closed` или `Cancelled`; начальник может отменить | `Order.status`, `Order.assigneeUserId`, `User.role`      | `PATCH /api/orders/{id}/status`              | `200 OK` / `403` / `409` |
| **ФТ-5** | Начальник участка видит все заказы и фильтрует по статусу и исполнителю      | `Order` (`status`, `assigneeUserId`)                         | `GET /api/orders?status=...&assigneeUserId=...` | `200 OK`           |
| **ФТ-6** | Нельзя создать заказ с неверными полями (`modelId` ≤ 0, короткие тексты)      | `Order` (`title`, `modelId`, `description`)                  | `POST /api/orders`                           | `400 Bad Request`     |
| **ФТ-7** | Вход по логину и паролю                                                       | `User` (`login`, `passwordHash`, `role`)                     | `POST /api/auth/login`                       | `200 OK` / `401`      |
| **ФТ-8** | Список отсортирован по дате создания, новые сверху                            | `Order.createdAt`                                            | `GET /api/orders`                            | `200 OK`              |

Если строку матрицы нельзя заполнить, значит модель данных или API нужно доработать.
