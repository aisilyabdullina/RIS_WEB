## 1. Трёхузловая схема архитектуры

```text
Vue 3 + Vite                    ASP.NET Core                     PostgreSQL
localhost:5173  ──────────────► localhost:5000  ───────────────► обычно :5432
                 HTTP (JSON)                     запросы к БД
                 Пример:                         (SQL / EF Core)
                 POST /api/orders
```

**архитектура web-ИС семестра**

Это и есть архитектура web-ИС семестра: три узла, две связи, один источник правды о заказах. Браузер никогда не обращается к базе данных напрямую.

---

## 2. Назначение узлов

| Узел                 | Технология           | Порт в разработке | Роль в системе КонтрОрдер |
| -------------------- | -------------------- | ----------------- | ------------------------- |
| Клиент (браузер)     | Vue 3 + Vite         | `5173`            | Отрисовывает экраны (вход, список заказов, создание заказа) и отправляет HTTP-запросы серверу. |
| Сервер (Backend API) | ASP.NET Core Web API | `5000`            | Проверяет поля, права ролей (`Manager`, `Chief`, `Engineer`), генерирует `id`, номер `ЗК-2026-0001` и начальный статус `New`, контролирует переходы статусов (`New`, `InProgress`, `Closed`, `Cancelled`). |
| База данных          | PostgreSQL           | `5432`            | Хранит таблицы заказов (`Orders`), моделей контроллеров (`ControllerModels`) и пользователей (`Users`) на диске (выполнение НФТ-1). |

## 3. Пример сквозного HTTP-запроса (Vue → ASP.NET Core)

Когда менеджер по заказам создаёт заказ на клиенте (`http://localhost:5173`), браузер отправляет запрос на сервер (`http://localhost:5000`):

- **Метод и путь:** `POST http://localhost:5000/api/orders`
- **Тело запроса (JSON):**

```json
{
  "title": "Контроллеры для линии фасовки",
  "modelId": 1,
  "description": "10 шт., интерфейс Modbus RTU, исполнение для цеха с повышенной температурой"
}
```

- **Ответ сервера при успехе (`201 Created`):**

```json
{
  "id": 17,
  "number": "ЗК-2026-0017",
  "title": "Контроллеры для линии фасовки",
  "modelId": 1,
  "description": "10 шт., интерфейс Modbus RTU, исполнение для цеха с повышенной температурой",
  "status": "New",
  "createdByUserId": 1,
  "assigneeUserId": null
}
```

Поля `id`, `number`, `status` и `assigneeUserId` формирует сервер; клиент их не присылает.

## 4. Почему браузер не пишет в БД напрямую

1. Код в браузере выполняется на устройстве пользователя и не является доверенной средой: любой сотрудник мог бы обойти проверку ролей.
2. Строка подключения к базе содержит секрет, которого не должно быть в клиентском коде.
3. Правила процесса (допустимые переходы статусов, обязательный исполнитель перед `InProgress`) должны проверяться в одном месте — на сервере.
