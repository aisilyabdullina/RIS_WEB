# ЛР3. Frontend — АИС «КонтрОрдер»

## Что сделано

Клиентская часть на Vue 3 + Vite (vue-router). Три экрана по заявке на тему:

| Экран | Путь | Кто видит | Что делает |
| ----- | ---- | --------- | ---------- |
| Вход в систему | `/login` | все | Ввод логина и пароля, ошибка при неверных данных (ФТ-7) |
| Список заказов | `/orders` | все роли, содержимое зависит от роли | Таблица заказов, новые сверху (ФТ-8) |
| Создание заказа | `/orders/new` | менеджер по заказам | Форма: наименование, модель из справочника, описание (ФТ-1, ФТ-6) |

## Поведение по ролям

| Роль | Что видит в списке | Какие действия доступны |
| ---- | ------------------ | ----------------------- |
| Менеджер по заказам | только свои заказы | кнопка «Создать заказ» |
| Начальник участка | все заказы, фильтры по статусу и исполнителю (ФТ-5) | назначить инженера на заказ `New` (ФТ-2), отменить заказ |
| Инженер-наладчик | только свои активные заказы | `New` → «В производство» (ФТ-3), `InProgress` → «Отгружен» или «Отменить» (ФТ-4) |

## Валидация формы создания заказа

- Наименование: 5–80 символов.
- Модель контроллера: обязательно выбрана (`modelId` > 0).
- Описание: 10–500 символов, счётчик символов под полем.

## Два режима работы

1. **Демо-режим (по умолчанию).** Backend не нужен: данные берутся из `src/mock.js`, который повторяет правила `api-contract.md` (права ролей, допустимые переходы статусов, ошибки). После обновления страницы заказы возвращаются к начальным.
2. **Реальный backend.** Скопировать `.env.example` в `.env.local`, поставить `VITE_USE_MOCK=false` и запустить ASP.NET Core на `http://localhost:5000`. Клиент обращается к тем же путям, что описаны в `api-contract.md`.

## Запуск

Нужен Node.js LTS.

```
cd frontend
npm install
npm run dev
```

Открыть `http://localhost:5173`.

## Как проверить критерии ЛР1 на интерфейсе

1. **Создать объект:** войти как `manager`, нажать «Создать заказ», заполнить форму — в списке появляется запись со статусом «Принят» и номером `ORD-2026-…`.
2. **Назначить исполнителя:** войти как `chief`, у заказа «Принят» выбрать инженера и нажать «Назначить» — статус не меняется, в колонке «Исполнитель» появляется ФИО.
3. **Перевод в работу:** войти как назначенный инженер, нажать «В производство» — статус «В производстве». Под другим инженером этот заказ в списке не виден.

## Заметки к защите ЛР3

- **Что показываем:** три экрана и разное поведение для трёх ролей.
- **Где правила:** права и переходы статусов проверяются в `mock.js`; в реальной системе их проверяет ASP.NET Core, а интерфейс только скрывает лишние кнопки.
- **Чего нет в семестре:** обновления списка в реальном времени, уведомлений и печати документов.
